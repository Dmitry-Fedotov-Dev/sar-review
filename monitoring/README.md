# Мониторинг SAR Review

Три уровня, независимые друг от друга. Работают по отдельности — можно взять
только то, что нужно.

| уровень | что даёт | нужен ли Docker |
|---|---|---|
| `/healthz` и `/metrics` | состояние сейчас, машиночитаемо | нет |
| Тревоги в Telegram | сообщение админам, когда платформа легла | нет |
| Prometheus + Grafana | история, графики, тренды | да |

В поле, где всё поднимают двумя командами на ноутбуке, достаточно первых
двух. Grafana нужна там, где есть эксплуатация и хотят видеть динамику.

## 1. Эндпоинты — работают всегда

```
GET /healthz    состояние + человеческие пояснения (JSON)
GET /metrics    те же данные в формате Prometheus
```

Оба **открыты без пароля**: внешнему монитору пароль от платформы иметь не
положено. Поэтому они отдают только эксплуатационные счётчики — ни имён
людей, ни телеграм-ников, ни ключей доступа, ни координат находок, ни имён
файлов операции. Это закреплено тестами (`tests/test_health_endpoints.py`).

Код ответа `/healthz` несёт смысл:

- **200** — всё в порядке **или есть предупреждения**;
- **503** — критично: воркер молчит, место кончилось, копий нет.

Предупреждение намеренно не поднимает 503. Диск на восьми гигабайтах — повод
заняться, а не будить дежурного; если 503 начнёт приходить по таким поводам,
на него перестанут реагировать ровно к моменту настоящей аварии.

## 2. Тревоги в Telegram

Проверку выполняет **бот**, раз в минуту опрашивая `/healthz`. Так сделано
потому, что лежащий сервис не может сообщить о том, что он лежит, а бот —
отдельный процесс и переживает падение веб-слоя.

Тревога уходит **не сразу**: состояние должно продержаться ~2.5 минуты. Одна
неудачная проверка — это сетевой чих, перезапуск сервера или моргнувший
туннель, а не авария. Сообщение приходит **один раз на смену состояния**, а
не каждую минуту; восстановление сообщается с длительностью простоя.

Команды администратора:

```
/status         состояние платформы прямо сейчас
/mute [часов]   отключить тревоги (по умолчанию 4 ч, максимум 24)
/unmute         включить обратно
```

Мьют **всегда временный** и включается сам. Молчащий навсегда мониторинг
хуже отсутствующего: он ещё и создаёт ложное ощущение, что за системой
следят. Пока тревоги замьючены, проверка пропускается целиком и состояние не
трогается — поэтому после снятия мьюта человек узнает, что сервис всё ещё
лежит, а не получит тишину.

> **Чего этот механизм не умеет.** Если выключится вся машина, бот умрёт
> вместе с платформой и не скажет **ничего**. Закрывается это только внешним
> пингом: заведите бесплатный uptime-монитор (UptimeRobot, Better Stack и
> подобные) на `https://ваш-адрес/healthz`. Это единственный способ узнать,
> что сервер выключился целиком.

## 3. Prometheus + Grafana

```bash
cd monitoring
cp .env.example .env          # и задайте GRAFANA_PASSWORD
docker compose up -d
```

Grafana: http://localhost:3000 · Prometheus: http://localhost:9090

Оба порта открыты **только на localhost** — наружу им торчать незачем; если
нужен удалённый доступ, заводите его через тот же туннель или VPN, а не
публикацией портов.

Дашборд «SAR Review — состояние платформы» приезжает сам: он лежит файлом в
`grafana/provisioning/dashboards/` и правится через git, а не мышкой в
интерфейсе. Панели:

- платформа, воркер, свободное место, возраст резервной копии, залипшие
  отчёты, зрители онлайн — плитки с порогами;
- файлы по статусам и свободное место во времени — по наклону видно, за
  сколько часов кончится диск;
- работа людей (ручные пометки, триаж) и накопленное покрытие просмотра;
- уровни всех проверок одной лентой.

### Если платформа не на этой же машине

Prometheus ходит к платформе по `host.docker.internal:8080` — это адрес
хоста из контейнера. Порт должен совпадать с `server.port` в
`sar_config.json`. Для удалённой платформы замените адрес в
`prometheus/prometheus.yml` на реальный.

### Про отсутствующие метрики

Если резервных копий нет ни одной, метрика `sar_backup_age_seconds`
**отсутствует**, и панель показывает «копий нет». Подменять её нулём нельзя:
`time() - 0` даёт полвека и выглядит как настоящие данные. Это же правило
действует для всех метрик — отсутствующее значение не выдаётся за ноль.
